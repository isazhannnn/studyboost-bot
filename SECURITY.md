# Безопасность StudyBoost

## Хранение секретов

Передавайте токен через переменную окружения `BOT_TOKEN` или локальный
`config.json`. Не отправляйте токены в Issues, PR, чаты и скриншоты.
Пример `config.json.example` содержит только заглушку.

Git игнорирует конфигурацию, ключи, базы SQLite, логи, резервные копии
и PDF с личными заметками. Игнорирование не удаляет уже отслеживаемые файлы
и не очищает старые коммиты.

HTTP-логи ограничены уровнем WARNING, обработчик ошибок не печатает
исключения с URL Telegram API или содержимым сообщений.
Не включайте подробные сетевые логи с рабочим токеном.

Бот обслуживает только личные чаты. Облачные интеграции отключены до
реализации полноценного OAuth; коды авторизации и токены не сохраняются.
Старый локальный `cloud_config.json` следует удалить после отзыва его
учётных данных, если вы пользовались предыдущей реализацией.

Команда `/privacy` объясняет хранение данных. `/delete_me` удаляет записи
текущего пользователя после подтверждения с одноразовым кодом.
База SQLite не зашифрована: владелец сервера имеет доступ к её содержимому.
Доступ к файлам сервера и резервным копиям нужно ограничить средствами ОС.
Удаление из базы не удаляет переписку Telegram или резервные копии.
Изменение целей ограничено владельцем записи, старые кнопки викторины
проверяются по идентификатору сессии, вопроса и сообщения.

CI проверяет текущие отслеживаемые файлы на распространённые форматы токенов
и приватные файлы. Это дополнительная проверка, а не полный аудит безопасности.

## Если секрет попал в репозиторий

1. Немедленно отзовите токен через @BotFather (`/revoke`) и получите новый.
   Для других сервисов отзовите соответствующие ключи у провайдера.
2. Замените секрет только в локальной конфигурации или окружении хостинга.
3. Проверьте действия бота, доступ к хостингу и журналы развёртывания.
4. Удалите секрет из истории Git после согласования переписывания истории.
   Для удаления всего файла из свежего клона:

   ```bash
   git filter-repo --sensitive-data-removal --invert-paths --path config.json
   ```

   Команда требует установленного `git-filter-repo`. Затем нужно обновить
   удалённые ссылки с контролем ожидаемых SHA и заново клонировать репозиторий.
   Не публикуйте резервную ветку с исходной историей.
5. При необходимости обратитесь в GitHub Support для очистки кешированных
   представлений. Старые копии и форки нельзя очистить одним push.

Удаление файла или переписывание истории не заменяет отзыв токена.
Подробнее: [инструкция GitHub](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/removing-sensitive-data-from-a-repository).

## Сообщить об уязвимости

Если в репозитории включён Private vulnerability reporting, используйте
вкладку Security → Report a vulnerability. Не публикуйте действующие секреты
или личные заметки в открытом Issue.
